# 项目开发与实验计划（V1，已扩展）

当前实现已升级为 V2：英文 GUI、三个情感二分类语料加 AG News 四分类，五种方法（TF-IDF + LR／SVM、Word2Vec + SVM、Word2Vec + BiLSTM、DistilBERT），并展示多种总体和每类指标。以下保留初始计划；现行结果与解释请见 [V2 项目报告](sentiment-project/report/classification-report-v2.md)。成员信息按用户要求暂不处理。

项目：跨数据集英文评论情感分析——TF-IDF 传统分类器与 DistilBERT 的效果、迁移能力及计算成本比较

英文题目：Cross-Dataset Sentiment Classification: Accuracy, Transferability and Cost of TF-IDF Baselines versus DistilBERT

计划日期：2026-11-06。状态：开发与实验方案，尚未实施训练，所有样本规模、参数和工时都是计划值，未报告实验成绩。

## 1. 目标、范围与课程要求

为需要快速阅读用户反馈的产品或运营人员，开发一个英文评论正负面分类演示工具。用户输入评论，选择训练来源，比较三个模型的判断，并查看真实实验结果。

研究贡献是统一实验条件下的系统比较与错误分析，不以提出新模型为目标。重点回答：

1. 在相同的标注训练规模下，DistilBERT 相对传统分类器有多大收益？
2. 从电影评论迁移到商家评论，效果是否下降？短影评与长影评之间是否也有变化？
3. 准确性收益是否值得训练、推理和模型体积的成本？

假设 H1：DistilBERT 在部分数据集优于词袋基线；H2：跨数据集性能通常下降；H3：传统模型在 CPU 推理与体积上更有优势。以上均为待检验假设，结果不支持假设也应如实报告。

核心范围固定为三数据集、三模型、同集评估、跨集评估、有限调参、错误分析及 Streamlit 界面。数据集数量是课程建议，本计划主动采用三个。论文复现属于可选要求，本项目参考论文和官方实现，但不声称复现论文原始分数。

暂不纳入多语言、多分类、聊天机器人、RAG、自建预训练或云端部署；可在完成核心内容后追加一个小规模扩展实验。

提交物依据用户提供的 PDF 第 4 页：不超过 10 分钟的视频、Python 代码、注明每人贡献并签名的小组反思、指定模板的 GAI 声明。视频由成员真人配音。每人完成 NTULearn 互评。完整 rubric、声明模板与准确扣分口径需从 syllabus/NTULearn 核对，不能从这份 PDF 推断所有评分细节。

## 2. 数据方案

使用以下固定数据源，并在下载时记录仓库 revision、加载库版本、原始 split、行 ID 和抽样清单。

- IMDb：`stanfordnlp/imdb`，电影长评论；官方标注 train 25,000、test 25,000。忽略无标注 split。从官方 train 分层抽取训练 6,000、验证 1,000；从官方 test 分层抽取测试 1,000。[数据卡](https://huggingface.co/datasets/stanfordnlp/imdb)
- Rotten Tomatoes：`cornell-movie-review-data/rotten_tomatoes`，电影短评／片段；官方 train 8,530、validation 1,066、test 1,066。分别从对应 split 分层抽取 6,000／1,000／1,000。[数据卡](https://huggingface.co/datasets/cornell-movie-review-data/rotten_tomatoes)；[原始发布页](https://www.cs.cornell.edu/people/pabo/movie-review-data/)
- Yelp Polarity：`fancyzhx/yelp_polarity`，商家与服务评论；官方 train 560,000、test 38,000。从官方 train 分层抽取训练 6,000、验证 1,000；从官方 test 分层抽取测试 1,000。[数据卡](https://huggingface.co/datasets/fancyzhx/yelp_polarity)

计划共 24,000 条，训练总量 18,000，验证与测试各 3,000。统一标签 0=negative、1=positive；读取数据集 features 核验映射，尤其不能把 Yelp 原始 CSV 的 1/2 标签与加载后 0/1 混用。每个 split 目标正负各半；达不到目标时报告实际数字，禁止复制样本凑数。

### 划分与防泄漏

1. 先做无标签的格式清理和去重，再冻结样本清单；抽样种子固定为 2026，与模型训练种子分开。
2. 保留官方 split 边界。清除空文本、HTML 标签、重复空白；保留否定词、标点与情感词，不做激进去停用词。
3. 对规范化文本计算哈希，跨三个数据源检查完全重复。测试样本优先保留，匹配的训练／验证样本移除；验证优先于训练。测试集之间相同文本记录并只保留在预先规定的一个数据源中。相互矛盾的重复标签剔除并记录。
4. 对短评与长评论的包含式重合做抽查，披露无法彻底排除的同电影、同作者和近重复问题。不要把“哈希不重复”等同于完全无泄漏。
5. 去重后从各自合法 split 补抽；若短评 split 不足 1,000，则按类别保留可用样本并报告实际数量，不跨 split 补样。
6. TF-IDF 词表与 IDF 仅在当前来源训练集上拟合；验证／测试只能 transform。跨集推理沿用来源模型的完整 pipeline。
7. 初期仅查看训练／验证结果。调参、功能选择、扩展实验方案全部冻结后，统一运行测试。测试错误分析只能用于最终解释，不反向修改模型后继续使用同一测试集宣称确认性结论。

数据审计产物：每集样本数、类别比例、英文词数及 DistilBERT token 长度分布、截断比例、移除数量、split 哈希交集为零的检查结果。三个语料并非三个完全独立的领域：IMDb 与 Rotten Tomatoes 都是电影；Yelp 涉及不同商家类别。迁移差异还包含文本长度、文体、标签定义和难度，不能全部归因于领域变化。

## 3. 模型与有限调参

### M1：TF-IDF + Logistic Regression

可解释、计算便宜的基线。TF-IDF 最大特征数 30,000，`min_df=2`，`sublinear_tf=True`，词 n-gram 在 (1,1)、(1,2) 中选择；正则化参数 C 在 0.1、1、10 中选择。通过 Pipeline 防止泄漏；solver 选择确定性的 `lbfgs`，记录收敛状态，必要时增加迭代上限。

### M2：TF-IDF + Linear SVM

使用与 M1 相同的清理规则和 TF-IDF 搜索空间；`LinearSVC` 的 C 在 0.1、1、10 中选择。固定实现与种子。若要比较“分类器本身”的影响，再报告两者在同一个预先指定的 unigram+bigram 设置下的验证结果；主实验比较的是各自经过相同预算选择的完整 pipeline。

### M3：微调 DistilBERT

从 `distilbert/distilbert-base-uncased` 加载基础预训练权重，加二分类头后训练。不能使用已经在 SST-2 等情感数据集上训练好的分类 checkpoint 冒充同样的训练条件。

- 最大长度 256，动态 padding；报告三个数据集的截断率。
- 学习率候选 2e-5、5e-5；AdamW；weight decay=0.01；warmup_ratio=0.1。
- 有效 batch size=16，最多 3 epochs。显存不足时减小 micro-batch 并用梯度累积维持有效 batch；硬件支持时才开启混合精度。
- 按每个 epoch 的验证 Macro-F1 保存最佳 checkpoint；相同分数选较早 epoch。无需再用测试集选 epoch。
- 先用训练种子 42 选择学习率，再固定该数据集的学习率，补做种子 43、44；固定数据样本与划分，报告三次训练的均值和样本标准差。

三个数据集分别训练各自来源模型，不先把它们混合。传统模型超参数也只按该来源验证集选择。M1/M2 同一数据、同一确定配置通常无需重复三次；不得把重复运行的零方差包装为随机稳定性证据。

参考：[TF-IDF 官方文档](https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html)、[LinearSVC 官方文档](https://scikit-learn.org/stable/modules/generated/sklearn.svm.LinearSVC.html)、[DistilBERT 模型卡](https://huggingface.co/distilbert/distilbert-base-uncased)、[官方微调教程](https://huggingface.co/docs/transformers/tasks/sequence_classification)、[DistilBERT 论文](https://arxiv.org/abs/1910.01108)。预训练语料和额外计算属于模型资源差异，不能把表现差异解释为仅由模型结构造成。

## 4. 实验协议与预算

### E0：数据审计与冒烟实验，必须

先跑通每集 200 条训练、100 条验证的端到端流程，检查标签、张量、损失、保存与加载，并测量一轮训练耗时和显存。小样本结果只用于调试，不能作为主实验成绩。

验收：能够从保存的模型重现预测；预测标签合法；指标脚本可处理两类；运行清单可追踪；没有划分重合。

### E1：同数据集比较，必须

三模型 × 三数据集，形成九个模型配置单元。每个单元使用相同来源的 train/validation/test。DistilBERT 每单元三种子，传统模型每单元一份固定结果，合计 15 份最终训练模型：6 份传统、9 份 Transformer。

主指标 Macro-F1；同时报告 Accuracy、每类 Precision/Recall/F1、样本支持数和混淆矩阵。三个数据集分别报告；如需总览，另外给三数据集 Macro-F1 的等权平均，不能混同为所有样本合并后的 F1。

展示种子差异时用均值±标准差，并明确它只描述训练随机性，不是测试集置信区间。对每集预先指定的 SVM 与 DistilBERT(seed=42) 做 1,000 次配对分层 bootstrap，输出 F1 差值的 95% 区间；它是条件于这些固定训练模型的测试样本不确定性，不能替代多次训练或证明因果。

### E2：跨数据集迁移，必须

固定 E1 模型，分别在另外两个测试集上预测，不使用目标数据集标签调参、校准阈值或微调。各模型输出来源×目标的 3×3 Macro-F1 矩阵：对角线为 E1，非对角线为迁移结果。

传统模型共 12 次非对角评估；DistilBERT 共 18 次非对角评估（三种子），不需要新增训练。报告逐目标、逐来源结果，避免用一个总体下降数字掩盖数据难度差异。

### E3：训练与推理成本，必须

- 训练：记录数据预处理、特征拟合、超参数搜索及最终拟合的独立墙钟时间；记录 CPU/GPU 型号、显存／内存峰值、模型磁盘体积和实际处理样本数。确定最终模型的搜索成本不能被隐藏。
- 推理：先预热 20 条，固定同一组 200 条测试文本，batch=1，重复 5 次；记录包含清理、分词／向量化、模型前向的端到端中位延迟与 p95（ms/条），不包含模型下载或加载。GPU 计时前后同步。
- 公平比较：所有模型首先做同一 CPU 的推理对比；Transformer 的 GPU 结果单独列出，不与传统模型 CPU 数字直接当作同硬件结论。统一线程和运行环境，计时避免并行抢占。
- LinearSVC 输出的是 decision margin，未经校准不能显示为概率；LR/DistilBERT 分数也不直接称为可靠置信度。

### E4：错误分析，必须

模型与实验方案冻结后，从三测试集各抽取最多 20 条模型错误／分歧样本，共最多 60 条；按标签、数据源和模型是否出错分层，记录抽样规则。若错误不足则分析全部，不凑数。固定 DistilBERT seed=42 作为案例模型。

人工记录否定、转折、讽刺、混合情感、领域用语、长文本截断、标注歧义等可多选类别，并保留原文、真值、三模型预测与解释。至少两位成员交叉检查其中 20 条；以文本证据解释，不假装注意力可视化就等于解释。

这些案例用于定性说明，不当作随机总体错误比例。模型正确但低分的例子也可展示，避免只挑成功案例。

### E5：训练数据量扩展，可选

仅在 IMDb 上，比较 1,000／3,000／6,000 条嵌套训练子集；固定原有验证与测试，比较 SVM 与 DistilBERT，参数沿用 E1，种子仅用 42。复用 6,000 条结果，新增 4 次训练（2 传统、2 Transformer）。在测试前决定是否执行，单种子结果标为探索性。资源不足首先取消本项。

### 训练量账目与资源决策

- 传统调参：3 数据集 × 2 模型 × 2 n-gram × 3 C = 36 次拟合；保存候选模型，最终六份直接复用选中的候选。
- DistilBERT：3 数据集 × 2 学习率 × seed42 = 6 次，再补每集最佳学习率的 seeds43/44 共 6 次，总计 12 次训练，其中 9 份进入主结果。最多 36 个训练 epoch。
- 以 6,000 条、有效 batch16 计算，每轮约 375 个 optimizer steps；12 次每次最多三轮约 13,500 steps，不含冒烟和可选实验。
- 暂按 4 人、可取得一张约 8GB 或以上 GPU 排期；具体显存能否容纳以 E0 为准，不保证某型号或免费配额可用。
- 第一天用 200～500 条、长度256的试跑估算完整训练与下载耗时；按实际吞吐估计剩余任务，并留约 30% 的调度余量。推测工时不能当作实测成本。
- 11/07 前若 GPU 无法取得或预计无法按时完成，统一缩减各集训练量至 3,000 并重新冻结三模型的相同抽样清单；优先取消可选实验。仍不可行则在查看测试结果前把 M3 改为冻结的 DistilBERT 表征+线性分类器，并修改题目和结论口径，明确它不再是微调实验。CPU 仍需试跑评估，不假定必然够快。

## 5. 开发模块与接口

建议 Python 技术栈：datasets、scikit-learn、PyTorch、Transformers、pandas、matplotlib/seaborn、Streamlit。开始时建立可运行环境，成功冒烟后锁定实际安装版本；记录模型和数据 revision，不盲目依赖不断变化的 latest。

模块职责：

1. 数据准备：输出 `text,label,dataset,split,sample_id,text_hash` 和固定 split manifest；审计结果含去重日志。
2. 传统训练：输入配置及 manifest，输出完整 TF-IDF Pipeline、候选验证指标和训练时间。
3. Transformer 训练：输入基础 checkpoint、配置、来源、seed，输出 tokenizer、最佳 checkpoint、训练曲线和资源日志。
4. 统一推理：输入文本列表、模型类型与训练来源，输出标签、原始分数、模型元信息。SVM score_type 标为 margin。
5. 统一评估：输入逐条预测和真值，输出指标、混淆矩阵、迁移矩阵及 bootstrap 结果。
6. 结果可视化：只读取真实结果文件生成图表，不手填实验数字。
7. Streamlit：加载缓存模型，文本输入、来源选择、三模型并排结果、实验图表及错误案例。

结果记录至少包含：run_id、dataset_revision、model_revision、source_dataset、target_dataset、train/val/test 清单哈希、model、seed、hyperparameters、selected_epoch、macro_f1、accuracy、每类指标、计时、硬件及 checkpoint 路径。逐条保存 sample_id、真值、预测、score_type、score。

必要检查集中在：标签映射、数据泄漏、指标一致性、加载后预测一致、空输入与过长输入。通过一份总入口或 notebook 能依次重建抽样、训练、评估和图表；无需为简单展示代码添加大量镜像测试。

Streamlit 验收：英文评论可输入；可选择训练来源；三个模型可以输出并显示耗时；空白输入有提示；截断会明确告知；SVM 不展示伪概率；结果页注明真实样本规模与硬件。启动后缓存权重，演示过程不现场训练。只提供正负两类，遇到中性或混合情感也会被迫二选一，界面应说明这一局限。使用预先指定的展示模型（DistilBERT seed42），不要按测试集挑最漂亮的 checkpoint。
