# v3 训练前实施补充规则

本文件补充正式设计在实际实施中遇到的边界，和design.lock一起冻结；不修改数据源、分区、输入或训练规模。

1. 二分类Yelp的`floor(C/3)`为0。尾部集合实际使用`max(1, floor(C/3))`，多分类同样采用这个公式。自然稀有组包含频数边界同分，全部同频时为NA。E3均衡基线不单独认定语义头尾；与偏斜条件比较时按该对比的头部排列解释，复用同一个均衡拟合。
2. Go覆盖集合先选频数最少的未覆盖标签，再在包含该标签的候选行中最大化新覆盖标签数，最后按稳定sample_id打破同分。覆盖集与alpha无关；alpha=0复用E1。T中不存在的标签显式记录，不从V/D/Q补足。
3. 单标签E1按seed和稳定ID的哈希排序取前缀，保留自然分布的抽样波动，不强制每档平衡。离线K-shot构造器用T标签分层；学习器只获其C×K行。
4. 相同训练集合的拟合入口必须先按sample_id排序，再使用训练seed生成epoch顺序。物理复用由集合、可见输入、模型、超参绑定、变体和训练seed共同决定；嵌套抽样顺序另外保留。
5. 数据源注册表的`multilabel`与接口的`multi_label`表示同一任务。Go始终保留28列，按Macro-AP选择，不能按互斥类别拆行。
6. 当前RTX4060 8GB已实际通过CUDA算术与神经模型单/多标签前向检查。此证据不代表反向传播、E0拟合或训练峰值内存已经验收。Transformer初始micro-batch=4、有效batch=16；BiLSTM有效batch=64。发生训练OOM时只按计划逐次减半micro-batch并增加累积步数，不改输入或样本。
7. 当前Windows固定wheel组合在Torch/Transformers之后加载Arrow dataset原生扩展会发生访问冲突；入口先加载Arrow dataset，已有隔离子进程回归覆盖。ModernBERT使用SDPA、关闭reference_compile，完整保留公共可见文本；其自身token数单列记录。
8. 本阶段只完成Task1–6及所需加载/验证。Task7–14中的学习器、完整训练器、统计与人审工具仍需后续实现；训练命令保持关闭。E0真实拟合、锚点选择、真实D试点、selection.lock、evaluation.freeze均不预填完成。

这些规则的成本是：Go抽样带覆盖约束；任务间仍存在语料混杂；配置完成不能代替完整训练smoke。它们均不构成新的能力结论。
